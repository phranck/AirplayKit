PlayableAirplay
Interface Example Usage Reference Source

Swift, macOS and Linux

Play to the speaker in the other room without taking the whole machine with you.

Apple's route picker moves the system's output, so everything on the Mac follows it. PlayableAirplay speaks RAOP to the receiver itself. One application streams to the kitchen, and the rest of the machine keeps playing where it always did.

01

Two types, and that is the interface

AirPlayDiscovery

Browses for the service AirPlay receivers advertise and reports the whole set each time it changes, sorted by name. It finds every receiver on the network, including the ones nothing is connected to, which is the part the system picker does not do.

Changes arrive on a queue you name, so a list on screen never updates from the sender's thread.

AirPlaySession

Pairs with one receiver and carries the audio. Writing never waits, because the thread producing live audio must not block, so a write that does not take the frames says whether the buffer is merely full or the receiver has hung up.

The volume it carries is the speaker's own control rather than a gain on the samples, so it survives a track change.

02

A file, start to finish

Read a file, turn it into what AirPlay carries, open a session, and keep it fed until the file runs out. On Apple's platforms AVFoundation does the conversion and takes any format the system can read. On Linux there is no AVFoundation, so the portable one takes a WAVE file that is already 16 bit stereo at 44100 and hands the bytes over as they are.

Both are lifted out of Sources/Demo/Demo.swift when this page is built, so what stands here is what the compiler saw. Both have been played to a speaker.

03

What it will not do

One session reaches one receiver. Several sessions at once would each start their own timeline against their own clock, so two speakers in the same room would drift apart within a minute. Holding them together needs a single timeline shared between them, and the sender underneath has not done that work, so this library does not offer it and does not pretend to.

It also does not resample. The audio goes in as interleaved signed 16 bit stereo at 44100 Hz, because that is what AirPlay carries, and anything else is converted before it arrives.

04

How to use it

It is a Swift package, and everything underneath it is built as part of that package. The C++ sender, ed25519 and Mbed TLS come from their own checkouts, so a clone and a build is the whole of it and nothing is fetched behind your back.

Then import PlayableAirplay and there is nothing else to set up. On Linux, browsing needs avahi-daemon running at the time, which is a matter of the machine rather than of the build.

PlayableAirplay is built on airplay2-sender-cpp, and it is not affiliated with Apple Inc.
